명함 사진 정리·주소록 도구 2주간 업무 정리

작성자: 신찬혁
정리 기간: 2026년 7월 25일 ~ 2026년 8월 7일


1. 작업 개요

이번 2주 동안 명함 사진을 Local AI로 분석하여 연락처를 추출하고, SQLite 주소록에 저장·관리하는 웹 도구의 주요 기능을 완성했다. 휴대폰 촬영 및 여러 장 연속 업로드, 명함 정보 추출, 주소록 검색과 중복 관리, CSV·vCard 내보내기까지 전체 사용 흐름을 구현하고 반응형 화면과 인식 안정성을 개선했다.


2. 주요 작업 내용

가. Local AI 연동 및 명함 정보 추출 개선

- LM Studio의 qwen3.5-9b-mlx 모델과 로컬 서버를 연동했다.
- 이름, 회사, 부서, 직책, 휴대폰, 유선전화, 이메일, 주소, 홈페이지를 JSON 형식으로 추출하도록 구성했다.
- 모델이 설명이나 잘못된 JSON을 함께 반환하여 분석에 실패하던 문제를 해결했다.
- 명함의 부서와 직책, 휴대폰과 유선전화, 이메일과 홈페이지가 서로 잘못 분류되지 않도록 프롬프트와 후처리 로직을 개선했다.
- 국내 전화번호와 국제전화 형식을 코드로 정리하고, 이메일 형식 검증과 홈페이지 주소 정규화를 적용했다.
- 명함이 아닌 일반 사진은 연락처로 저장되지 않도록 명함 여부 판정 기능을 추가했다.
- Local AI 연결 상태를 실제 LM Studio 상태 API와 연동하여 화면 하단에 표시했다.

나. 명함 업로드 기능 개선

- 데스크톱 파일 업로드와 휴대폰 카메라 촬영 업로드를 모두 지원하도록 구현했다.
- 휴대폰에서 촬영 또는 사진 선택 방식을 선택할 수 있는 메뉴를 추가했다.
- 여러 장의 명함을 한 번에 선택한 뒤 한 장씩 순서대로 분석하도록 연속 업로드 기능을 구현했다.
- 분석 중인 명함, 분석 대기, 확인 대기, 저장 완료, 건너뜀, 분석 실패 상태를 화면에 표시했다.
- 건너뛴 명함을 다시 선택하면 재분석할 수 있도록 구현했다.
- 고해상도 사진은 긴 변을 1600px로 축소하여 Local AI로 전달하도록 개선했다.
- 세로 방향 이미지와 휴대폰 EXIF 방향 정보를 처리하여 명함이 잘못 회전되는 문제를 개선했다.
- 명함이 한 장만 등록된 경우에는 이동할 다음 항목이 없으므로 '다음 명함' 버튼이 비활성화되도록 수정했다.

다. 확인·수정 및 저장 기능

- 원본 명함 사진과 추출 결과를 나란히 확인할 수 있는 화면을 구현했다.
- 저장 전에 9개 필드를 사용자가 직접 수정할 수 있도록 구성했다.
- 확인 후 저장 버튼을 눌러야 SQLite 데이터베이스에 등록되도록 구현했다.
- 여러 장을 업로드한 경우 현재 명함을 저장하면 다음 명함 분석이 자동으로 시작되도록 만들었다.

라. 명함관리 페이지 구현

- SQLite에 저장된 실제 명함 데이터를 최근 등록순으로 표시했다.
- 이름 또는 회사명으로 검색할 수 있는 검색창을 추가했다.
- 명함 카드의 크기를 305×204px로 유지하면서 여러 장이 자연스럽게 줄바꿈되도록 정렬했다.
- 저장 시 배정된 명함 디자인이 목록 순서가 바뀌어도 유지되도록 수정했다.
- 명함을 클릭하면 9개 필드 전체를 확인할 수 있는 상세 모달을 추가했다.
- 상세 모달에서 연락처 수정과 삭제가 가능하도록 구현했다.
- 홈페이지 주소를 클릭하면 새 탭에서 해당 사이트가 열리도록 연결했다.

마. 중복 명함 관리

- 전화번호가 같거나 이름과 회사가 같은 명함을 중복 후보로 판정하도록 구현했다.
- 중복 모아보기 버튼을 누르면 같은 중복 그룹의 명함이 붙어서 표시되도록 구성했다.
- 중복 후보 그룹이 화면 가운데에서 시작하고 한 줄에 최대 3개까지 표시되도록 반응형으로 정렬했다.
- 신규 저장 시 기존 중복 명함의 이름, 회사, 전화번호를 보여주고 별도 등록 여부를 선택할 수 있도록 구현했다.
- 중복 후보 그룹의 병합 버튼을 누르면 최신 명함을 기준으로 빈 정보를 보완하고, 나머지 중복 명함을 삭제하도록 구현했다.
- 병합 도중 오류가 발생하면 데이터가 일부만 변경되지 않도록 데이터베이스 트랜잭션을 적용했다.

바. 주소록 내보내기

- 전체 주소록을 CSV 파일로 다운로드하는 기능을 완성했다.
- CSV 파일에 UTF-8 BOM을 적용하여 Excel에서 한글이 깨지지 않도록 처리했다.
- 전체 주소록을 vCard 3.0 형식으로 내려받는 선택 기능을 추가했다.

사. 반응형 UI 및 사용 환경 개선

- 휴대폰, 태블릿, 일반 모니터, 대형 모니터 및 TV 화면에 대응하는 반응형 UI를 구현했다.
- 큰 화면에서 UI가 지나치게 커지지 않으면서 명함 내용이 잘리지 않도록 크기와 간격을 조정했다.
- 휴대폰에서 업로드 영역의 불필요한 공백과 입력 필드 배치를 개선했다.
- 홈 화면의 콘텐츠가 짧아도 푸터가 화면 아래에 위치하도록 수정했다.
- 같은 Wi-Fi에 연결된 휴대폰에서 개발 PC의 로컬 서버 주소로 접속하여 촬영·업로드할 수 있도록 구성했다.

아. 설치 및 실행 문서 정리

- README에 Node.js 및 LM Studio 요구 사양을 작성했다.
- 프로젝트 설치, 환경변수 설정, Local AI 모델 준비, 서버 실행 방법을 정리했다.
- 휴대폰 접속 방법과 Local AI 연결 문제, 처리 지연 문제의 확인 방법을 작성했다.
- Windows와 macOS 사이에서 프로젝트를 옮길 때 node_modules를 삭제하고 npm install을 다시 실행해야 하는 내용을 확인했다.


3. 테스트 및 자체 평가

- 서로 다른 촬영 조건의 명함 20장을 사용하여 정확도를 평가했다.
- PC 이미지 10장과 휴대폰 촬영 이미지 10장을 테스트했다.
- 회전, 저조도, 흐림, 빛 반사, 구김, 물에 젖음, 이물질 등의 조건을 포함했다.
- 전체 분석 성공률은 100%로 20장 모두 분석 자체에는 성공했다.
- 9개 필드 전체 인식률은 165/180으로 91.7%였다.
- 핵심 필드인 이름, 휴대폰, 이메일의 인식률은 56/60으로 93.3%였다.
- 전체 평균 처리시간은 55.4초였다.
- 20장 중 13장이 1분 이내에 처리되어 1분 이내 처리 성공률은 65%였다.
- 자동화 테스트를 작성하여 업로드, 정규화, 명함 판정, 주소록 관리, 중복 병합, 내보내기 및 반응형 동작을 검증했다.


4. 작업 중 발생한 문제와 해결 내용

가. 여러 장 분석 실패

여러 이미지를 동시에 Local AI에 전달할 때 분석 실패가 발생했다. 업로드한 명함을 큐에 저장하고 한 장씩 순서대로 분석하도록 변경하여 문제를 해결했다.

나. JSON 파싱 실패

Local AI가 JSON 앞뒤에 설명이나 코드 블록을 추가하면서 서버에서 결과를 읽지 못하는 문제가 있었다. 응답에서 유효한 JSON 객체를 찾아 파싱하도록 로직을 보완했다.

다. 휴대폰 이미지 회전 문제

휴대폰으로 촬영한 사진이 옆으로 돌아가거나 세로로 표시되는 문제가 있었다. EXIF 방향을 반영하고 필요한 경우에만 이미지를 가로 방향으로 변환하도록 수정했다.

라. 필드 분류 오류

부서와 직책이 합쳐지거나 해외 휴대전화가 유선전화로 들어가는 문제가 발생했다. 프롬프트의 필드 분류 기준을 구체화하고 전화번호, 홈페이지 및 주소 후처리 로직을 추가했다.

마. 처리시간 초과

일부 명함에서 누락 필드를 재확인하기 위해 Local AI 요청이 추가로 실행되면서 처리시간이 1분을 넘었다. 이미지 크기 축소와 요청·프롬프트 최적화로 평균 처리시간을 55.4초까지 줄였지만, 모든 명함이 1분 이내에 처리되지는 않아 추가 개선이 필요하다.

7. 종합 결과

이번 2주 동안 명함 업로드부터 Local AI 분석, 결과 확인 및 수정, SQLite 저장, 주소록 검색·수정·삭제, 중복 병합, CSV·vCard 내보내기까지 핵심 사용 흐름을 완성했다. 다양한 촬영 조건의 명함 20장 테스트에서 전체 인식률 91.7%와 분석 성공률 100%를 확인했다. 현재 주요 기능은 모두 동작하며, 남은 작업은 일부 처리시간과 인식 오류 개선, 모델 후보 비교 자료 및 최종 시연 준비이다.

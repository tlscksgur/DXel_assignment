# 명함 상세 모달 수정·삭제 설계

## 목표

BCM 페이지의 명함 상세 모달에서 현재 명함의 9개 연락처 필드를 수정하거나 명함을 삭제할 수 있게 한다.

## 사용자 흐름

1. 사용자가 목록에서 명함을 선택하면 기존 상세 모달이 열린다.
2. `수정`을 누르면 상세 값이 입력 필드로 바뀌고 버튼은 `저장`, `취소`로 전환된다.
3. `저장`을 누르면 `PUT /api/cards/:id`로 9개 필드를 전송한다.
4. 저장 성공 시 목록 데이터와 모달을 갱신하고 다시 읽기 상태로 돌아간다.
5. `취소`를 누르면 변경값을 버리고 기존 상세 화면으로 돌아간다.
6. `삭제`를 누르면 확인창을 표시하고, 확인한 경우 `DELETE /api/cards/:id`를 호출한다.
7. 삭제 성공 시 모달을 닫고 현재 검색·중복 보기 조건으로 목록을 다시 불러온다.

## UI 설계

- 기존 카드 디자인, 회사 배지, 명함 번호, 닫기 버튼을 유지한다.
- 상세 필드 아래에 작업 영역을 배치한다.
- 읽기 상태: `수정`, `삭제` 버튼을 표시한다.
- 편집 상태: `저장`, `취소` 버튼을 표시한다.
- 주소는 여러 줄 입력이 가능한 `textarea`, 나머지는 한 줄 `input`을 사용한다.
- 저장·삭제 요청 중에는 관련 버튼을 비활성화하고 상태 문구를 표시한다.
- 휴대폰에서도 버튼이 잘리지 않도록 작업 영역을 줄바꿈 가능하게 만든다.

## 데이터와 오류 처리

- 수정 대상은 이름, 회사, 부서, 직책, 휴대폰, 유선전화, 이메일, 홈페이지, 주소다.
- 서버가 이미 수행하는 전화번호 정규화, 이메일 검증, 홈페이지 정리를 그대로 사용한다.
- 수정 요청에는 기존 `image_path`를 함께 전달해 이미지 경로가 사라지지 않게 한다.
- 중복 응답(409)이 오면 사용자에게 기존 중복을 허용해 저장할지 확인하고, 허용하면 `allowDuplicate: true`로 한 번 재요청한다.
- API 오류 시 모달과 사용자의 편집값을 유지하고 오류 메시지를 보여준다.

## 검증

- 상세 HTML에 9개 수정 필드와 작업 버튼이 생성되는지 자동 테스트한다.
- 수정 요청이 올바른 URL, 메서드, JSON 본문으로 전송되는지 테스트한다.
- 삭제 요청이 올바른 URL과 메서드로 전송되는지 테스트한다.
- 기존 카드 렌더링, 중복 그룹, 홈페이지 링크 테스트가 모두 계속 통과해야 한다.

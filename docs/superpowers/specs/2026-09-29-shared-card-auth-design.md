# 명함 공유 열람 및 계정 기능 설계안

## 상태

사용자 검토용 초안입니다. 셀프 가입, 비로그인 사용자의 읽기 전용 열람, 명함 등록자만 수정할 수 있는 권한을 다룹니다. 이 문서를 검토하고 승인하기 전에는 구현을 시작하지 않습니다.

## 목표

로그인하지 않아도 하나의 공유 명함 목록을 살펴볼 수 있게 하되, 로그인 계정으로 명함 등록자를 구분하고 개인별 그룹과 즐겨찾기를 관리합니다. 계정마다 공유 명함을 복제하지 않습니다.

## 현재 프로젝트 구조

- Express 5와 SQLite, 정적 HTML 페이지 및 브라우저 JavaScript로 구성되어 있습니다.
- 현재 `business_cards`에 공유 명함 정보와 태그, `group_name`, `is_favorite`가 함께 저장됩니다.
- 명함 목록·상세 조회, 명함 변경, 내보내기, 업로드 이미지가 현재 로그인 확인 없이 제공됩니다.
- 페이지 상단 메뉴가 `index.html`, `BCM.html`, `cardAdd.html`, `cardImport.html`, `cardTrash.html`에 각각 있습니다.
- 저장소에는 계정·세션 테이블이나 메일 전송 설정이 없습니다.

## 사용자 화면 및 동작

- 전달받은 상단 메뉴 디자인을 사용합니다. 브랜드와 페이지 메뉴, ‘명함 등록’, 오른쪽 계정 메뉴를 배치합니다.
- 로그아웃 상태에서는 로그인 메뉴를 표시합니다. 로그인 상태에서는 프로필 이미지 또는 이니셜, 표시 이름, 드롭다운을 표시합니다.
- 계정 메뉴에는 프로필 설정과 로그아웃을 둡니다. ‘명함 공유’와 ‘데이터 백업’은 이번 버전에서 실제 기능 없이 준비 중인 임시 메뉴로 표시하며, 작동하는 것처럼 오해하게 만들지 않습니다.
- 가입 시 표시 이름, 이메일, 비밀번호만 받습니다. 직책·부서·회사명은 요구하지 않습니다.
- 프로필 설정에서 표시 이름과 비밀번호를 변경할 수 있습니다. 이번 버전에는 계정 삭제나 관리자 계정 관리 기능을 넣지 않습니다.
- 이메일을 정규화해 로그인에 사용합니다. 누구나 관리자 승인 없이 가입할 수 있지만, 실제 계정 사용 전 이메일 인증이 필요합니다.

## 열람 및 권한 규칙

| 기능 | 로그아웃 상태 | 로그인 상태 |
| --- | --- | --- |
| 명함 목록·상세 정보·만남 메모·명함 및 로고 이미지 열람 | 전체 명함 열람 가능, 읽기 전용 | 전체 명함 열람 가능 |
| 명함 등록 및 파일 가져오기 | 불가 | 가능. 새 명함은 로그인 계정의 등록 명함으로 저장 |
| 명함 수정·태그 변경·휴지통 이동·복원·완전 삭제·병합 | 불가 | 본인이 등록한 명함만 가능. 병합은 관련된 모든 명함의 등록자여야 가능 |
| 즐겨찾기 및 그룹 | 사용 불가 | 로그인 계정별로 별도 관리 |
| 명함 태그 | 공유 명함의 태그 열람 | 본인이 등록한 명함의 태그만 변경 가능 |
| CSV/vCard 내보내기 | 불가 | 전체 공유 명함 내보내기 가능 |

비로그인 상태에서 열람할 수 있다는 것은 배포 환경의 네트워크 접근 통제를 통과한 모든 사용자가 명함의 모든 정보와 이미지를 볼 수 있다는 뜻입니다. 쓰기 권한은 서버에서 강제해야 하며 화면에서 버튼만 숨기는 것으로 대신하지 않습니다.

## 데이터 구조

- 정규화한 이메일, 표시 이름, 비밀번호 해시, 이메일 인증 시각 및 생성·변경 시각을 저장하는 `users` 테이블을 추가합니다.
- 임의의 세션 토큰 원문은 저장하지 않습니다. 토큰 해시, 사용자 ID, 만료 시각을 보관하는 `sessions` 테이블을 추가합니다.
- 비밀번호 재설정 토큰은 해시만 저장하고 만료 및 일회 사용 상태를 기록하는 `password_reset_tokens` 테이블을 추가합니다.
- `business_cards`에 `created_by`를 추가합니다. 새 명함의 등록자는 요청 데이터가 아니라 로그인 세션에서 정합니다.
- 즐겨찾기는 사용자·명함 조합을 유일하게 제한하는 `card_favorites(user_id, card_id)` 테이블로 옮깁니다.
- 그룹은 사용자·명함별 그룹을 저장하는 `user_card_groups(user_id, card_id, group_name)` 테이블로 옮깁니다. 사용자마다 한 명함에 그룹 하나를 지정할 수 있습니다.
- 태그는 공유 명함의 `business_cards.tags`에 유지합니다. 기존 전역 그룹·즐겨찾기 열은 이전 후 기준 데이터로 사용하지 않습니다.
- 현재 개발용 명함은 테스트 데이터로 간주합니다. 애플리케이션 시작 시 개발자의 로컬 DB를 자동 삭제하지 않습니다. 실제 배포 전 운영 DB는 테스트 명함 없이 초기화하며, 기존 명함을 임의 계정 소유로 지정하지 않습니다.

## 인증 및 보안

- Node 내장 `scrypt`로 비밀번호를 해시하고, 비교 시 타이밍 안전 비교를 사용합니다.
- 무작위·불투명·만료 기한이 있는 `HttpOnly`, `SameSite=Lax` 쿠키를 사용하고 HTTPS에서는 `Secure`를 설정합니다. 로그인 시 세션 토큰을 교체하고 로그아웃 시 폐기합니다.
- 쿠키 인증을 사용하는 변경 요청은 CSRF 공격을 방어하고, 로그인 및 재설정 요청은 횟수를 제한합니다.
- 이메일 인증 및 비밀번호 재설정 메일은 소스 코드 밖의 회사 메일 설정을 사용합니다. 비밀번호 재설정 링크는 30분 후 만료되고 한 번만 쓸 수 있으며, 토큰 해시만 저장합니다. 이메일 등록 여부가 응답으로 드러나지 않게 합니다.
- 메일 전송 설정이 없으면 인증·재설정 API는 명확한 서비스 이용 불가 응답을 반환하고 동작을 거부합니다. 메일 설정 및 실제 발송을 시험하기 전에는 이 기능이 운영 가능하다고 간주하지 않습니다.
- 비로그인 접근은 공유 명함 조회 및 명함 이미지 읽기로 제한합니다. 계정, 개인 그룹·즐겨찾기, 휴지통, 가져오기, 명함 변경, 내보내기 API는 해당 작업에 맞는 로그인 확인을 요구합니다.
- 일괄 작업과 중복 병합을 포함해 모든 API에서 명함 소유권을 확인합니다. 다른 사람의 명함을 포함하는 요청은 일부만 반영하지 않고 전체를 거부합니다.

## 이번 버전에서 제외할 항목

- 명함 공유 링크와 데이터 백업은 실제 기능 없이 임시 메뉴로만 둡니다.
- 관리자 화면, 가입 승인 절차, 계정 삭제, 관리자가 대신하는 비밀번호 재설정은 넣지 않습니다.
- 비로그인 사용자의 내보내기, 휴지통 및 가져오기 접근은 제공하지 않습니다.
- 명함별 비공개 기능은 제공하지 않습니다. 배포 환경의 네트워크 통제를 거친 비로그인 사용자도 모든 활성 명함 정보를 볼 수 있습니다.

## 완료 기준

1. 로그인하지 않은 방문자는 활성 명함과 이미지를 모두 열람할 수 있지만, 명함 변경·개인 그룹 및 즐겨찾기·휴지통·가져오기·CSV/vCard 다운로드는 할 수 없습니다.
2. 누구나 표시 이름, 이메일, 비밀번호로 가입할 수 있고, 이메일 인증 후 로그인할 수 있습니다.
3. 두 계정이 같은 명함 목록을 보더라도 서로의 그룹 및 즐겨찾기를 볼 수 없고 덮어쓸 수도 없습니다.
4. 새 명함에 로그인한 등록자가 기록됩니다. 다른 계정은 그 명함을 수정·태그 변경·휴지통 이동·복원·완전 삭제·병합할 수 없습니다.
5. 로그인 사용자는 공유 명함 전체를 내보낼 수 있고, 로그아웃 상태의 내보내기 요청은 서버가 거부합니다.
6. 비밀번호 재설정 토큰은 추측하기 어렵고, 저장 시 해시 처리되며, 30분 후 만료되고 한 번만 사용할 수 있습니다. 요청 결과로 이메일 가입 여부가 노출되지 않습니다.
7. 상단 메뉴가 전달된 로그인 전·후 화면을 따르고, 계정 메뉴의 공유·백업 항목은 임시 기능임을 분명히 보여줍니다.
8. 기존 테스트 데이터는 애플리케이션 시작만으로 삭제되지 않으며, 운영 환경은 테스트 명함이 없는 상태로 시작할 수 있습니다.

## 위험 및 필요한 준비

- 이메일 인증 및 분실 비밀번호 재설정에는 회사 메일 전송 서버와 운영 URL 설정이 필요합니다. 이를 설정하고 실제 메일을 시험하기 전까지 두 기능은 운영 가능한 상태가 아닙니다.
- 비로그인 열람은 배포 환경의 네트워크 접근을 통과한 방문자에게 전체 연락처와 만남 메모를 공개합니다.
- 전역 그룹·즐겨찾기를 계정별 데이터로 옮기면 관련 API와 화면 상태가 바뀝니다. 계정 간 데이터 분리와 모든 변경 API의 권한 확인을 시험해야 합니다.

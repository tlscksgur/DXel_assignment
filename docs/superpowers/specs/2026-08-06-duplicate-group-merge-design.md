# 중복 후보 그룹 병합 설계

## 목적

명함 관리 페이지의 `중복 모아보기`에서 중복 후보 그룹을 한 번에 병합한다. 병합 후에는 대표 명함 한 장만 남기고 나머지 중복 레코드는 삭제한다.

## 사용자 흐름

1. 사용자가 `중복 모아보기`를 누른다.
2. 각 중복 후보 그룹의 제목 영역에 `병합` 버튼이 표시된다.
3. 사용자가 버튼을 누르면 최근 등록 명함을 기준으로 병합하며 나머지 항목이 삭제된다는 확인창이 표시된다.
4. 확인하면 서버가 그룹 전체를 병합한다.
5. 성공하면 명함 목록을 다시 불러오고, 병합된 그룹이 중복 목록에서 사라진다.
6. 취소하거나 실패하면 기존 명함은 그대로 유지된다.

## 병합 규칙

- 그룹에서 가장 최근에 등록된 명함을 대표 명함으로 사용한다.
- 대표 명함에 값이 있는 필드는 그대로 유지한다.
- 대표 명함의 빈 필드는 나머지 명함을 최근 등록순으로 확인해 처음 발견한 값으로 채운다.
- 이름, 회사, 부서, 직책, 휴대폰, 유선전화, 이메일, 주소, 홈페이지, 이미지 경로에 같은 규칙을 적용한다.
- 이미지와 카드 디자인은 대표 명함을 우선하므로 대표 명함의 이미지 경로가 있으면 바꾸지 않는다.
- 병합이 완료되면 대표 명함을 제외한 그룹의 레코드를 삭제한다.

## 서버 설계

- 기존 단일 저장용 병합 API와 구분되는 그룹 병합 API를 추가한다.
- 요청에는 병합할 명함 ID 배열을 전달한다.
- 서버는 전달받은 ID가 두 개 이상인지 검증하고 DB에서 실제 레코드를 조회한다.
- `created_at`과 `id`를 기준으로 가장 최근 명함을 대표로 선택한다.
- SQLite 트랜잭션 안에서 대표 명함 갱신과 나머지 레코드 삭제를 수행한다.
- 갱신이나 삭제 중 하나라도 실패하면 롤백한다.
- 응답에는 대표 명함 ID와 삭제된 명함 수를 포함한다.

## 화면 설계

- `중복 후보 N` 제목 오른쪽에 기존 장수 표시와 병합 버튼을 함께 배치한다.
- 버튼은 현재 중복 그룹의 강조색을 사용하되 장수 표시와 구분되는 클릭 가능한 형태로 만든다.
- 병합 요청 중에는 버튼을 비활성화하고 `병합 중`으로 표시한다.
- 성공하면 목록을 새로 불러오고 결과 요약도 갱신한다.
- 오류가 발생하면 경고창으로 서버 메시지를 표시하고 버튼을 원래 상태로 되돌린다.

## 오류 처리

- ID가 두 개 미만이면 400 응답을 반환한다.
- 요청한 명함 일부가 존재하지 않으면 404 응답을 반환한다.
- DB 작업 실패 시 트랜잭션을 롤백하고 500 응답을 반환한다.
- 중복 클릭은 비활성화 상태로 차단한다.

## 테스트 기준

- 중복 그룹마다 병합 버튼이 렌더링된다.
- 버튼에는 해당 그룹의 모든 명함 ID가 연결된다.
- 최근 명함의 기존 값이 오래된 값으로 덮어써지지 않는다.
- 최근 명함의 빈 필드는 오래된 명함의 값으로 채워진다.
- 병합 후 대표 명함만 남는다.
- 잘못된 ID 또는 DB 오류가 발생하면 기존 명함이 삭제되지 않는다.
- 병합 성공 후 중복 목록이 다시 로드된다.

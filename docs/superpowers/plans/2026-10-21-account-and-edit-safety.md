# 계정 선점 및 명함 오수정 수정

범위: 리뷰 3·4번만 수정한다. 앞서 수정한 1·2번 권한 가드를 유지하고 5·6·7번과 운영 배포는 변경하지 않는다.

설계: 이메일 인증 요청은 유효한 30분/1회용 토큰과 최종 비밀번호를 함께 요구한다. 인증 트랜잭션에서 비밀번호 해시를 교체한 후 계정을 활성화해 미인증 사전 가입자의 비밀번호가 남지 않게 한다. 인증 화면에는 최종 비밀번호 입력을 추가하고 브라우저 저장소나 링크에는 비밀번호를 저장하지 않는다. 잘못된 비밀번호는 422로 거부하여 만료 링크 처리와 구분한다. 기존 인증된 계정은 변경하지 않는다.

명함 편집은 최초 `contact.id`와 편집 화면 문맥을 저장한다. 비동기 요청/중복 재시도는 원래 명함만 대상으로 하며, 다른 명함이나 새 편집 화면으로 이동하면 이전 요청이 화면을 덮어쓰거나 상세창을 다시 열지 않게 한다.

- [x] `test/auth-routes.test.js`: 사전 가입·정상 소유자 인증·비밀번호 교체, 토큰 단독 인증 거부, 잘못된 비밀번호 재시도, 토큰 만료/재사용 거부를 먼저 실패로 확인했다.
- [x] `auth/routes.js`: 최종 비밀번호 검증 및 원자적 교체·활성화. 가입/인증 안내와 API 문서를 갱신했다. 없는/만료 토큰은 해싱 전에 조회로 거부하고 트랜잭션 안에서 다시 검증한다.
- [x] `public/verify-email.html`, `public/js/authPages.js`, `test/verification-ui.test.js`: 최종 비밀번호 입력/전달, 비밀번호 오류 시 폼 유지, 성공 시 입력 삭제, 기존 인증/재전송 상태를 유지했다.
- [x] 독립 작업: `public/js/cardManagement.js`, `test/card-save-race.test.js`에서 대상 ID/편집 문맥 고정 및 요청 지연 회귀 테스트를 먼저 추가하고 수정했다.
- [x] 전체 300개 테스트 통과, JS 문법·diff 검사 및 독립 읽기 전용 검토 완료. 실제 브라우저 검증은 연결 도구 오류로 미수행. 커밋·배포·운영 서버 변경 없음. 남은 문제는 5·6·7번이다.

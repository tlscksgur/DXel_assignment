# 하위 경로 배포 구현 계획

목표: `/businessCard/` 아래에서 페이지, API, 업로드 이미지, 로그인 쿠키, 인증·재설정 메일이 동작한다. 기존 루트 개발 실행도 지원한다.

구성: APP_BASE_URL의 경로로 앱 경로를 결정한다. 브라우저 API와 이미지 주소는 현재 페이지에 상대적인 주소를 사용한다. DB에 저장된 `/uploads/파일명`은 그대로 유지한다. Nginx는 외부 7777에서 경로별 웹을 나누고 명함 Node 서비스(127.0.0.1:3000)로 전체 경로를 전달한다.

- [x] 배포 경로·메일 URL·쿠키 경로의 회귀 테스트 작성 및 실패 확인.
- [x] 경로 설정 검증과 Express 경로 제한, 로그인 이동 경로 적용.
- [x] 브라우저 API·내보내기·이미지 상대 경로 적용.
- [x] 메일 인증·재전송·비밀번호 재설정 URL과 쿠키 경로 적용.
- [x] Ubuntu systemd/Nginx 예시 및 SMTP·외부 URL·HTTPS 설정 안내 작성.
- [x] 관련 테스트와 실제 HTTP 하위 경로 동작 검증. 기존 전체 테스트 실패와 새 실패 구분.

검증 결과: 전체 188개 테스트 통과. 의존성 잠금 파일 갱신 후 npm audit 취약점 0개. 실제 Node 서버의 앱 경로·보호 페이지 이동·계정 API 및 이미지 상대 주소를 검증했다. 브라우저 자동화는 도구의 sandboxPolicy 메타데이터 오류로 실행되지 않았다. 회사 서버 SSH는 비대화형 인증이 불가하여 원격 설정·실제 SMTP 발송·TLS 적용은 미완료다.

제약: 서버 SSH 접속 정보가 없어 원격 설정을 직접 변경할 수 없다. SMTP 비밀번호를 문서·Git에 저장하지 않는다. 운영 HTTPS 검증을 해제하지 않는다. HTTP 연결 확인은 개발 모드에서만 수행한다. 인증 메일의 실제 발송과 서버 적용은 SMTP 설정 및 운영자 실행이 필요하다.

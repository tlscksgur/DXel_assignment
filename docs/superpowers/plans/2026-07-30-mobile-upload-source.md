# 모바일 업로드 방식 선택 구현 계획

> **자동화 작업자 참고:** 필수 하위 기술로 `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans`를 사용해 이 계획을 작업별로 구현한다. 진행 상황은 체크박스(`- [ ]`) 형식으로 관리한다.

**목표:** 모바일 명함 업로드에서 촬영과 갤러리 선택을 구분한다.

**설계:** 촬영용과 갤러리용 파일 입력을 분리하고 하나의 파일 대기열 처리 함수를 공유한다. 모바일에서는 자체 선택창을, 데스크톱에서는 갤러리 입력을 바로 연다.

**기술 구성:** HTML, CSS, JavaScript, Node.js 내장 테스트 러너

---

### 작업 1: 실패하는 선택창 테스트

**파일:**
- 수정: `test/upload-flow.test.js`

- [ ] 촬영 입력, 갤러리 입력, 선택창 HTML을 검사한다.
- [ ] 모바일 업로드 버튼이 선택창을 열고 각 버튼이 대응 입력을 실행하는지 검사한다.
- [ ] 기존 다중 업로드 테스트가 갤러리 입력을 사용하도록 변경한다.
- [ ] 테스트를 실행해 새 요소와 이벤트가 없어 실패하는지 확인한다.

### 작업 2: 선택창 구현

**파일:**
- 수정: `public/cardAdd.html`
- 수정: `public/js/cardAdd.js`
- 수정: `public/css/cardAdd.css`

- [ ] 두 파일 입력과 하단 선택창을 추가한다.
- [ ] 모바일·데스크톱 업로드 버튼 동작을 연결한다.
- [ ] 두 입력이 공통 큐 처리 함수를 사용하게 한다.
- [ ] 모바일 선택창과 배경 스타일을 추가한다.

### 작업 3: 검증

**파일:**
- 테스트: `test/upload-flow.test.js`

- [ ] `npm test`로 전체 기능을 검증한다.
- [ ] `node --check public/js/cardAdd.js`와 `git diff --check`를 실행한다.

# 명함 권한 우회 수정 계획

범위: 리뷰 1·2번의 비로그인/타인 명함 변경 우회만 수정한다. 외부 접근, 가입, 편집 비동기, 휴지통 UI, vCard, AI 타임아웃은 변경하지 않는다.

설계: 공통 미들웨어는 Express와 동일하게 대소문자를 구분하지 않고 명함 API의 인증·출처를 검사한다. 소유권 검사는 실제 변경 라우트에 붙여 `req.params.id`를 검증하며, 일괄 변경은 API와 동일한 `parseCardIds`를 사용한다. 잘못된 입력은 거부하고 미인식으로 통과시키지 않는다. 관리자 예외는 같은 판정을 유지한다.

- [x] 실제 서버/임시 DB에서 대소문자, 후행 슬래시, 선행 0, 인코딩 ID, 문자열 일괄 ID의 우회 회귀 테스트를 추가하고 기존 코드의 실패를 확인했다.
- [x] `auth/card-access.js`에 라우트용 소유권 미들웨어와 공통 ID 파서를 제공하고 `server.js`의 공유 명함 변경 라우트 10개에 연결했다. 전역 URL 정규식 기반 소유권 분기와 중복된 파서를 제거했다.
- [x] 기존 미들웨어 단위 테스트는 실제 라우트 가드 체인에 맞추고 서버 VM fixture는 추가 라우트 인자를 허용한다.
- [x] 비로그인 거부, 타인 거부, 등록자/관리자 허용, 개인 즐겨찾기·그룹 유지 및 잘못된 일괄 ID 거부를 검증한다.
- [x] 전체 테스트 284개 통과, JS 문법/diff 검사 완료. 독립 읽기 전용 검토에서 이번 범위의 추가 결함을 발견하지 못했다. 커밋·푸시·운영 서버 변경은 하지 않았다.

남은 리뷰 항목: 미인증 계정 선점, 편집 저장 중 대상 ID 변경, 휴지통 확인 취소 시 버튼 비활성, vCard 이스케이프 복원, AI 응답 본문 타임아웃. 이번 변경에서 수정하지 않았다.
